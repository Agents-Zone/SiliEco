The Silieco CLI both connects local runtimes and manages workspaces, tasks, agents, and automations from the terminal. This page covers the common paths; the flags your installed version supports are always defined by each command's own `--help`.

## Installation

**macOS / Linux**

```bash
curl -fsSL https://raw.githubusercontent.com/silieco-ai/silieco/main/scripts/install.sh | bash
```

With Homebrew installed, you can also run:

```bash
brew install silieco-ai/tap/silieco
```

**Windows PowerShell**

```powershell
irm https://raw.githubusercontent.com/silieco-ai/silieco/main/scripts/install.ps1 | iex
```

Confirm the install:

```bash
silieco version
```

## First connection

Connect to Silieco Cloud:

```bash
silieco setup
```

Connect to a self-hosted instance:

```bash
silieco setup self-host \
  --server-url https://api.example.com \
  --app-url https://app.example.com
```

`setup` saves the server address, opens a browser to complete sign-in, and starts the daemon. When it finishes, check:

```bash
silieco auth status
silieco daemon status
```

If you only need to sign in again without overwriting other configuration, run `silieco login`. On a machine without a browser, create a personal access token in the web settings first, then enter it with:

```bash
silieco login --token
```

The command prompts you to paste the token in the terminal, keeping the full value out of shell history.

## Choosing a workspace

List workspaces and switch the default:

```bash
silieco workspace list
silieco workspace switch <slug>
```

Subsequent commands use this workspace. A single command can override it with `--workspace-id`, or you can set `SILIECO_WORKSPACE_ID`.

Invite members:

```bash
silieco workspace member invite teammate@example.com
silieco workspace member invite admin@example.com --role admin
```

## Common task operations

```bash
# View and search
silieco task list
silieco task get SILI-123
silieco task search "login failure"

# Create and update
silieco task create --title "Fix login failure"
silieco task status SILI-123 in_progress
silieco task assign SILI-123 --to "Backend Agent"

# Comments and runs
silieco task comment list SILI-123
silieco task comment add SILI-123 --content "Check the regression tests first"
silieco task runs SILI-123
```

Read long descriptions or comments from stdin to avoid dealing with newlines and quoting:

```bash
silieco task create --title "Upgrade notes" --description-stdin < notes.md
silieco task comment add SILI-123 --content-stdin < review.md
```

View the messages of a single run, or stop a run:

```bash
silieco task run-messages <run-id> --task SILI-123
silieco task cancel-run <run-id> --task SILI-123
```

## Agents and skills

```bash
silieco agent list
silieco agent get <agent-id>
silieco agent create --help
silieco agent update <agent-id> --help

silieco skill list
silieco skill get <skill-id>
silieco skill import --url <skill-url>
silieco agent skills add <agent-id> --skill-ids <skill-id>
```

When an import hits a skill with the same name, the default is to stop without modifying existing content. Pick by intent:

```bash
silieco skill import --url <skill-url> --on-conflict overwrite
silieco skill import --url <skill-url> --on-conflict rename
silieco skill import --url <skill-url> --on-conflict skip
```

`overwrite` is only allowed for the skill's creator and preserves the original ID and agent bindings.

## Daemon and runtimes

```bash
silieco daemon start
silieco daemon stop
silieco daemon restart
silieco daemon status --output json
silieco daemon logs --follow

silieco runtime list
silieco runtime rename <runtime-id> "Office Mac"
silieco runtime usage <runtime-id>
silieco runtime activity <runtime-id>
```

Deleting a runtime that still has active agents bound to it is refused by default. `silieco runtime delete <id> --cascade` also archives those agents and cancels their active runs.

See [Daemon and runtimes](/daemon-runtimes) for how it works and for custom profiles.

## Command overview

| Command | Purpose |
| --- | --- |
| `task` | Create, update, assign, and search tasks; manage comments, subscribers, labels, properties, and runs |
| `project` | Manage projects and their resources |
| `label`, `property` | Manage workspace labels and custom properties |
| `agent`, `skill`, `squad` | Manage agents, skills, and squads |
| `autopilot` | Manage automations, triggers, and run history |
| `workspace` | Create, view, and switch workspaces, and invite members |
| `repo` | Manage workspace repositories and check them out locally |
| `daemon`, `runtime` | Start and stop the local daemon; view and manage runtimes |
| `attachment` | Upload or download attachments |
| `user profile` | View or update the current user's profile |
| `auth`, `login`, `setup` | Log in, check auth status, and initialize a connection |
| `config` | View or edit the current CLI profile's local configuration |
| `update`, `version` | Update the CLI or print the version |

`silieco chat` reads **the external chat session an agent is currently handling**; it is mainly for agents in chat integrations, not a general command for browsing arbitrary workspace conversations.

## IDs and output formats

Tasks use keys like `SILI-123` or full UUIDs; short UUID prefixes are not accepted.

`list` commands for other resources usually print copyable short IDs and support `--full-id` for the full UUID. When a short ID is ambiguous, the CLI asks for more characters or the full UUID. Short run IDs also require `--task` to identify the owning task.

Many commands support structured output:

```bash
silieco task list --output json
silieco agent list --output json
```

Scripts should use JSON output rather than parsing the terminal-oriented tables. The output formats and pagination flags each command supports are defined by `silieco <command> --help`.

## Profiles and configuration

The default configuration lives in `~/.silieco/config.json`. Use `--profile <name>` to isolate a separate set of server address, token, default workspace, and daemon state:

```bash
silieco setup self-host --profile staging \
  --server-url https://api.staging.example.com \
  --app-url https://app.staging.example.com

silieco task list --profile staging
```

Named profiles live in `~/.silieco/profiles/<name>/config.json`. Inspect the current values:

```bash
silieco config show
silieco config show --profile staging
```

<Callout type="warning">
CLI configuration files contain tokens that can access Silieco as you. Don't commit them to a repository, upload them to logs, or share them with others.
</Callout>

## Command reference

The tables below cover every current top-level command, grouped the way the CLI itself groups them. All commands accept the global flags `--server-url`, `--workspace-id`, `--profile`, and `--debug`. `--output` is registered per command, and the default format varies: `list` commands default to a table, while `get` and `create` commands mostly default to JSON. Full flags are defined by `silieco <command> --help`.

### Core

| Command | Subcommand | Purpose | Key flags |
| --- | --- | --- | --- |
| `task` | `list` | List tasks | `--status`, `--priority`, `--assignee`, `--project`, `--metadata` (repeatable), `--limit`, `--offset`, `--sort`, `--full-id` |
| | `get <id>` | Show a single task | |
| | `create` | Create a task | `--title` (required), `--description` / `--description-stdin` / `--description-file`, `--status`, `--priority`, `--assignee`, `--parent`, `--stage`, `--project`, `--start-date`, `--due-date`, `--attachment` (repeatable) |
| | `update <id>` | Update task fields | Same fields as `create`, plus `--position` |
| | `assign <id>` | Assign or unassign | `--to` (fuzzy name match against members, agents, and squads), `--to-id`, `--unassign` |
| | `status <id> <status>` | Change status | |
| | `reorder <id>` | Move within a column | |
| | `search <query>` | Search tasks | `--limit`, `--include-closed` |
| | `children <id>` | List sub-tasks grouped by stage | |
| | `pull-requests <id>` | List linked PRs | |
| | `comment list/add/delete/resolve/unresolve` | Manage comments | `add`: `--content` / `--content-stdin` / `--content-file`, `--parent`, `--attachment`; `list`: `--since`, `--thread`, `--tail` |
| | `subscriber list/add/remove <task-id>` | Manage subscribers | `--user`, `--user-id` (defaults to the current user) |
| | `label list/add/remove <task-id>` | Manage labels on a task | |

| | `runs <id>` | View an agent's runs | |

| | `trigger <id>` | Trigger a run manually | |

| | `trigger-add/trigger-update/trigger-delete/trigger-rotate-url` | Manage schedule and webhook triggers | |

| `repo` | `list/add/remove/checkout` | Manage workspace repositories and check them out locally | `--url` (repeatable); `checkout`: `--ref` |
| `skill` | `list/get/create/update/delete` | Manage skills | |

| Command | Subcommand | Purpose | Key flags |
| --- | --- | --- | --- |
| `daemon` | `start` | Start the local daemon | `--foreground`, `--device-name`, `--runtime-name`, `--poll-interval`, `--heartbeat-interval`, `--agent-timeout` (`0` means no limit), `--max-concurrent-runs`, `--no-auto-update`; each has a matching `SILIECO_*` environment variable |

| | `profile set-path/unset-path <profile-id>` | Pin a local executable path (local only, never uploaded to the server) | |

### Additional

| Command | Subcommand | Purpose | Key flags |
| --- | --- | --- | --- |
| `auth` | `status` / `logout` | Check auth status; `logout` only deletes the locally saved token and does not revoke it on the server | |
| `user` | `profile get/update` | View or update the current user's profile | |
| `login` | — | Sign in via the browser and configure all workspaces automatically | `--token` (prompts interactively in the terminal when passed without a value) |

| `version` | — | Print version information | `--output` (`text` or `json`) |
