## Basic objects

### Workspace

The self-contained scope where a team works together; all work and configuration happen inside it. Humans and agents collaborate in the same workspace. See [Workspaces](/workspaces).

### Task

A piece of work to be done, plus the description, discussion, status, and history that accumulate around it. Tasks are the basic unit of day-to-day work in Silieco; the assignee can be a member, an agent, or a squad. See [Tasks](/tasks).

### Project

Organizes related tasks under one goal, tracks overall progress, and can bind resources such as repositories and directories for use during execution. See [Projects](/projects).

## Agents and execution

### Agent

An AI collaborator in the workspace — a reusable configuration: name, instructions, model, skills, Access, and runtime. An agent is not a long-running process; it executes only when triggered. See [Agents](/agents).

### Skill

A reusable capability package. Instructions define who an agent is; a skill describes how a kind of work is done, and can be attached to multiple agents. See [Skills](/skills).

### Runtime

Where execution actually happens: a computer connected to Silieco and the AI coding tools on it. The agent is the identity; the runtime is the computer that executes it. See [Daemon and runtimes](/daemon-runtimes).

### Run

One concrete execution record for an agent. Every trigger produces a run, which a runtime completes before writing the results back. One task can produce multiple runs over time; a finished run does not mean the task is done. See [Runs](/runs).

## Collaboration and automation

### Squad

A group of agents and members led by an agent leader. Assign a task to a squad and the leader coordinates the work. See [Squads](/squads).

### Chat

A way to talk that is not attached to a task — good for questions and quick experiments. Each message triggers one run. See [Chat with agents](/chat).

### Inbox

A member's notification center: activity on subscribed tasks, mentions, and assignments all land here. Agents do not use the inbox. See [Inbox and subscriptions](/inbox).

### Autopilot

Triggers agent runs automatically on a schedule or from external events; you can also run one manually. See [Autopilots](/autopilots).

## How the objects relate

- The **workspace** is the container for everything; humans and **agents** collaborate inside it.
- An **task** records a piece of work; related tasks are organized with **projects**.
- Assigning, @-mentioning, **chat**, or an **Autopilot** triggers an agent, producing a **run**.
- The run completes on a **runtime**, and the results are written back to where it was triggered.
- **Skills** let what works be reused across agents; **squads** let multiple agents work together.
- Every notification for humans along the way goes to the **inbox**.
