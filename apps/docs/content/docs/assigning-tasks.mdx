When a piece of work needs an agent to own it over time, assign the task to it. The agent reads the task's description and discussion, does the work with its own configuration and skills, and writes progress and results back to the same task.

When you only need the agent to handle one specific request without changing ownership, use an [@-mention in a comment](/mentioning-agents) instead.

## Assign and start a run

1. Open a task and click **Assignee**.
2. Pick an agent or a squad.
3. Review the agent about to start in the confirmation dialog.
4. Add a handoff note if needed, then choose **Start**.

![Assignment confirmation dialog: add a handoff note, or choose not to start yet](/images/docs/assign-confirm-dialog.png)

The handoff note applies to this run only — use it for scope, ordering, or what to focus on this time. Requirements that should hold long term belong in the task, the project description, or the agent instructions.

When you assign to a squad, the squad becomes the task's assignee and the squad leader starts first. It decides whether to hand work to other members, following how the squad operates.

## Execution after assignment

Silieco creates a [run](/runs) for the agent. Once an online runtime claims the run, it invokes the AI coding tool on that machine; progress, comments, and results then appear in the task.

If the runtime is temporarily offline, the run waits in the queue; a run is bound to its runtime and never moves to another machine.

While executing, the agent can:

- read the task's description, fields, and comments;
- use its bound skills, MCP servers, and project context;
- read files, run commands, and make changes in its local working directory;
- post comments and update the task status.

What it can actually do is still limited by the agent's configuration, the runtime environment, and your permission to run it.

During the run, the agent is expected to manage the task's status by convention (typically `todo` → `in_progress`, then `in_review` on delivery) — these actions appear under the agent's identity in the timeline. Run lifecycle and task status are separate: a run completing does not by itself change the task status.

When the assignee is a [squad](/squads), the same expectations apply: Silieco enqueues the leader, who moves the parent task to `in_progress` on the first turn and keeps it there while members work. The leader only moves it to `in_review` once the overall goal is met — a successful first dispatch is not completion.

## Assign without starting

**Don't start yet** in the confirmation dialog saves the assignee without creating a run for this run. Use it to settle ownership first and start once the background or dependencies are ready.

`backlog` doesn't start a run on assignment either. Execution only follows after you move the task out of `backlog`, or ask the assignee for something in a follow-up comment.

Only `backlog` works this way. Tasks already in `done` or `cancelled` still start a run immediately when assigned or reassigned to an agent.

## Assignment permissions

Whether you can assign an agent is decided by its Access:

- **Only me**: only the agent's owner can run it;
- **Specific people**: the owner and the listed members can run it;
- **Entire workspace**: every workspace member can run it.

Workspace owners and admins can manage agents, but being able to see one doesn't mean being able to run it. The assignee picker disables agents you can't run. See [Agents](/agents#permissions-and-access) for the full rules.

## Change or remove the assignee

Switching the assignee to another agent starts a new run for the new assignee; picking a member only changes the assignee and doesn't invoke any AI coding tool. Removing the assignee doesn't create a run either.

<Callout type="warning">
Changing the assignee, unassigning, or changing the task status doesn't stop a run that has already started. To interrupt it, stop the corresponding run in the execution log.
</Callout>

## Use the CLI

```bash
silieco task assign SILI-42 --to "Agent name"
silieco task assign SILI-42 --unassign
```

In scripts, use `--to-id <uuid>` to avoid matching the wrong object with the same name. Look up UUIDs with `silieco agent list --output json` or `silieco workspace member list --output json`.
