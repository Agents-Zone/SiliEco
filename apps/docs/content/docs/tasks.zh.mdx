Task 是 Silieco 中安排工作的基本单位：一项功能、一个 bug、一次调研，任何需要成员或智能体负责推进的工作。围绕它的讨论、状态变化和每次执行都留在同一处，无需再从聊天记录或终端日志中拼接上下文。

## Task 的组成

| 内容 | 用途 |
|---|---|
| **标题和描述** | 目标、背景、要求和验收条件。 |
| **状态和优先级** | 工作处于哪个阶段，先处理什么。 |
| **负责人** | 工作区成员、智能体或小队。 |
| **日期、标签和自定义属性** | 计划、分类和团队自己的字段。 |
| **项目和父子关系** | 归入更大的工作范围，或拆成子 task。 |
| **动态和执行日志** | 评论、状态变化、执行和智能体返回的结果。 |


## 创建 task

在 **Tasks** 页面或项目中新建，填写标题即可，其余属性随时补充。

每个 task 有一个编号，例如 `SILI-123`。数字在工作区内递增；管理员修改工作区的 task 前缀后，编号会用新前缀显示。详见[工作区](/workspaces#创建工作区)。

## 选择负责人

| 负责人 | 效果 |
|---|---|
| **成员** | 由这位成员负责跟进，不创建执行。 |
| **智能体** | 为该智能体创建一条执行。 |
| **小队** | 由小队 leader 接收，再决定交给谁处理。 |

分配给智能体或小队时，task 不在 `backlog` 就会立即入队；运行时离线时，Task留在队列中等待。已归档的智能体和小队不能被分配。

分配不会绕过智能体的访问范围（Access）；分配给小队时，校验的是 leader 的 Access。详见[分配 task 给智能体](/assigning-tasks)。

## 状态

| 状态 | 含义 |
|---|---|
| `backlog` | 暂不启动。已分配给智能体的 task 需离开 `backlog` 后才会创建执行。 |
| `todo` | 已明确，等待开始。 |
| `in_progress` | 正在处理。 |
| `in_review` | 已有结果，等待检查。 |
| `done` | 已完成。 |
| `blocked` | 暂时无法继续。 |
| `cancelled` | 不再继续，保留记录。 |

状态之间没有固定流转，成员和智能体都可以直接修改。

把 task 分配给智能体后，智能体开工时应把状态从 `backlog` / `todo` 推到 `in_progress`，交付后再推到 `in_review`。这些状态变更由智能体在运行中通过 Silieco CLI 显式写入——run 开始或完成时，服务端不会自动改 task 状态（下面两个系统例外除外）。`done` 通常留给人工确认，或由集成完成（例如带关闭意图的 PR 合并）。

<Callout type="info">
两个变化由系统执行：

- 执行失败，且该 task 没有其他执行、也没有触发重试时，`in_progress` 回到 `todo`。
- 关联的 GitHub PR 带关闭意图合并，且没有其他仍处于 open 或 draft 的关联 PR 时，task 变为 `done`。
</Callout>

## Task 与执行

Task 是持续存在的工作记录；[执行（run）](/runs)是智能体的一次具体执行。一个 task 可以先后产生多条执行——第一次实现、补充修改、再次检查。执行"已完成"只表示这一次执行结束；task 是否完成，以 task 的状态为准。

## 项目和子 task

一个 task 最多属于一个[项目](/projects)，项目为其中的执行提供共享说明和资源；移到另一个项目不会产生副本。

较大的工作可以拆成子 task：父 task 保留整体目标，子 task 各自独立推进。父子状态互不联动。

子 task 可以设置**阶段**（stage），按 1、2、3 分批推进。当前最早未完成阶段的全部子 task 到达 `done` 或 `cancelled` 时，父 task 会收到"子Task完成"通知；父 task 的负责人是智能体时，它会被唤醒并决定是否推进下一阶段。未设置阶段的子 task 视为同一批，全部结束时通知一次。

## 切换视图

Tasks 页面提供列表、看板、表格、甘特图和泳道五种视图，可按状态、负责人、项目和其他属性筛选、排序，展示的都是同一批 task。

## 删除 task

任何工作区成员都可以删除 task。

<Callout type="warning">
删除不可恢复：task 及其评论、附件和关联记录会被永久移除，尚未结束的执行会被取消。不再继续时把状态改为 `cancelled`，讨论和结果仍可查阅。
</Callout>
