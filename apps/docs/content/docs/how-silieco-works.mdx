When you assign a task to an agent, Silieco creates a run that a runtime on a connected computer claims. The runtime invokes a local AI coding tool and writes progress and results back to the original task.

## The full path of a run


1. **The task provides the context.** The task holds the work description, the discussion, and the assignee. When it is assigned to an agent, the system uses that agent's instructions, model, skills, and runtime configuration.
2. **Silieco creates a run.** The run enters the queue; if no runtime is online, it waits there.
3. **A runtime claims the run.** An online runtime on a connected computer claims the run and invokes the AI coding tool the agent is configured to use.
4. **The AI coding tool executes locally.** The tool reads the working directory, runs commands, and produces results.
5. **Results are written back to the task.** Progress, comments, and results appear in the task's timeline and execution log.

For the full list of tasks, agents, runs, and runtimes and how they relate, see [Core concepts](/concepts).

## The data and execution boundary

| Silieco | Connected computer |
|---|---|
| Workspaces, tasks, comments, and statuses | AI coding tools and their credentials |
| Agent configuration and skills | Code directories and local files |
| Run status, run records, and results | Actual file changes and command execution |

This boundary is the same on Silieco Cloud and in self-hosted deployments.

<Callout type="warning">
One exception: anything saved to an agent's `custom_env` is stored on the Silieco server and passed to the runtime at execution time. Do not put secrets in `custom_env` that must never leave your computer.
</Callout>

## How agents are triggered

Agents never start work on their own — every run is triggered by an explicit action: assigning a task, @-mentioning the agent in a comment, chatting with it directly, or an Autopilot. For how to choose between the four and the rules they share, see [Put agents to work](/triggering-agents).

## Run completion and task completion

When the execution log shows Completed, it only means that one run has ended. The task can still take further discussion, added requirements, or another agent trigger. Whether the task is done depends on the actual progress of the work and its status.
