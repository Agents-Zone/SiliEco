把一个 task 分配给智能体后，Silieco 会创建一条执行，由连接电脑上的运行时领取。运行时调用本地 AI 编程工具，并把进度和结果写回原来的 task。

## 一次执行的完整链路


1. **Task 提供上下文。** Task 保存工作说明、讨论和负责人。分配给智能体后，系统会使用该智能体的指令、模型、skill 和运行时配置。
2. **Silieco 创建执行。** 执行进入队列；没有在线运行时时，它会在队列中等待。
3. **运行时领取Task。** 连接电脑上的在线运行时领取Task，并调用智能体配置的 AI 编程工具。
4. **AI 编程工具在本地执行。** 工具读取工作目录、运行命令并生成结果。
5. **结果写回 task。** 进度、评论和结果显示在 task 的时间线与执行日志中。

task、智能体、执行和运行时的完整清单与关系，见[核心概念](/concepts)。

## 数据与执行的边界

| Silieco | 连接的电脑 |
|---|---|
| 工作区、task、评论和状态 | AI 编程工具及其凭据 |
| 智能体配置与 skill | 代码目录和本地文件 |
| 执行的状态、执行记录和结果 | 实际的文件修改与命令执行 |

这条边界在 Silieco Cloud 和自托管中相同。

<Callout type="warning">
有一个例外：保存到智能体 `custom_env` 的内容会存放在 Silieco 服务器端，执行时传给运行时。不希望离开你电脑的 secret，不要写进 `custom_env`。
</Callout>

## 智能体的触发方式

智能体不会自己开始工作，每次执行都由一个明确的动作触发：分配 task、在评论中 @智能体、直接对话，或自动化。四种方式的选择和通用规则见[让智能体开始工作](/triggering-agents)。

## 执行结束与 task 完成

执行日志显示"已完成"，只表示这一次执行已经结束。Task 仍然可以继续讨论、补充要求或再次触发智能体。Task 是否完成，以实际工作进展和它的状态为准。
