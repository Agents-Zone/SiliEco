创建阶段模板：步骤与它如何驱动看板

阶段模板是流程动态配置的入口。研发要实现的核心是"创建模板"这个配置动作，以及模板保存后如何驱动下游。本页讲两件事：创建模板分几步、每步配什么；配好之后看板的列、卡片状态、流转规则如何全部由模板生成。

模板如何驱动看板

模板保存后，用户创建事项选了这个模板，看板就按模板自动生成。看板的列、卡片状态、流转规则全部来自模板，换个模板看板就变样。以投标模板为例。

除看板外，阶段模板的字段还驱动下面这些功能。每个都是模板配置的直接下游，研发实现时从模板字段读取即可。

阶段列表

事项创建与实例化

用户创建事项时，只能从项目允许的模板里选。选定后深拷贝模板生成事项状态机，事项从此按这套阶段跑。

输入 / 输出路径

产物自动同步

事项进入阶段时，平台按模板声明的路径从 Git 拉取输入、推送输出，无需事项自己管文件位置。

所需 Skills

Agent 能力匹配

阶段所需 Skills 是执行前置条件。Agent 缺 Skill 时平台告警，由 Owner 追加或换 Agent。

门控 + 回退

决策与回退

转换边上的门控决定哪里要暂停等决策；回退规则决定打回到哪个阶段。两者都配置在模板里。
